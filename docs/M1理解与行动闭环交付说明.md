# M1：可解释理解与生命体行动

交付日期：2026-10-15。数据库 head：`0005_m1_memory_runtime`。

## 已完成的闭环

用户写下想法或回应带回问题 → 追加成长证据 → 显式聚合生成候选理解 → 用户校准、修正或删除 → 按当前授权形成上下文快照 → 触发 manual/cron 共用 tick → 看见行动理由，并可通过快照回放当时使用的理解。

## 主要行为

1. 候选理解按固定议题聚合，权重达到 100 且包含用户自撰证据才生成。未知议题保留证据，浏览不能单独开启理解，生成流程不推断立场。
2. 四种校准都会追加独立证据和修正记录。“只是最近”只作近期关注，14 天后过期；“理解错了”不再参与决策；“我在反对”保留关注并标明用户并未赞同原观点。
3. 编辑创建新理解并保留替代链；删除理解使其退出未来决策；写入携带预期版本，过期页面无法覆盖新修正。修正历史保留前后内容、时间与 trace ID。
4. 私人探索与社交推荐分别生成快照。被拒绝、删除、替代、过期或撤回授权的理解被排除；平台快照失效后，其派生证据也不再进入新上下文。
5. 分数按 30 天半衰期惰性衰减。快照采用内容寻址，历史快照不会被后续修改覆盖。
6. 两种后端适配器共用记忆规则，tick 保存 `context_snapshot_id`。页面读取不调用大模型。
7. 桌面生命体页与移动端理解面板支持持续输入、查看证据和修正记录、逐条校准、编辑、删除、社交授权、暂停和恢复使用理解。带回问题的回应可以保存为应用内证据。

## 数据库变更

`0004` 建立证据幂等键、可重算文本、理解版本链与上下文快照表。`0005` 补充理解议题、修正前后快照和 tick 到上下文的引用，并将粗粒度上下文唯一键替换为内容寻址。MySQL 需要保留独立 lifeform 索引以满足外键，迁移可根据实际结构续跑部分已执行的 DDL。

历史证据的补列文本是可识别的占位内容，不能当作原始摘要。重新推导平台内容仍应从已保存的原始导入快照开始。
