# 前端模块化重构

## 范围与原则

本轮将原先集中于 `prototype/src/Prototype.tsx` 的业务拆为可独立维护的模块，保留 React、TypeScript、Vite、原有布局和交互，不引入全局状态库或新路由。采用 codebase-design 的小 Interface、完整业务 Implementation 原则：任务提交与轮询集中处理，调用页面不再重复理解任务协议。

本次明确批准的模块拆分仅扩展 app-owned 源码组织，未改 `App.tsx`、`main.tsx`、`styles.css`、`mobile/`、设备素材或受保护构建运行时，也没有修改 `prototype.css`。

## 目录职责

```text
prototype/src/
  Prototype.tsx              模式分发入口
  app/                       桌面与移动端布局、导航和页面编排
  features/
    onboarding/              四问、诞生、共享创建 Hook
    world/                   世界展示、目录合并与目录加载 Hook
    understandings/          理解展示、编辑、校准、证据与授权管理
    exploration/             探索设置、任务提交、轮询与生命周期
    encounters/              相遇读取、回放与关系幕布
    connections/             私密决定与邀请展示
  shared/
    api/                     HTTP 传输、错误与共享契约类型
    config/                  议题、校准、状态标签
    assets/                  形态与场景素材映射
    experience/              真实与独立演示模式判定
    ui/                      移动端热点
  demo/                      演示素材配置、建号、校准与初始化
  mobile/                    原有受保护设备运行时，未修改
```

依赖方向为应用外壳 → 业务模块 → 共享传输与契约。业务模块不得反向导入应用外壳。桌面和移动端共享业务逻辑而非强制共享所有布局。共享类型目前集中保存契约，后续可随实际改动进一步按领域归属拆分，不要求提前建立大量空目录或转发模块。

## 数据与状态

- 应用外壳保存当前世界、页面与相遇等跨页面状态。
- 展开、表单草稿、编辑目标与幕布位置保留在局部展示中。
- `useOnboarding` 管理创建提交，显式重试沿用同一幂等键，阻止并发重复提交，卸载时取消请求。
- `useExploration` 管理探索设置、乐观更新与失败回滚；切换用户和卸载取消旧任务，避免旧结果覆盖新用户。
- `useUnderstandings` 管理修改、校准、证据历史与授权请求，展示只保留输入状态。
- `useIslandCatalog` 管理目录读取与取消，目录失败继续保留原有可识别的素材降级行为。

所有 app-owned HTTP 请求经过 `shared/api/client.ts`，不再散落原生 fetch。`requestJson` 统一解析错误并提供 HTTP 状态；需要区分 404 的相遇读取仍使用底层 Response Interface。

## 统一探索任务

`advanceWorld` 提交一次操作，`waitForTick` 只轮询已提交任务；默认最多 20 次、间隔 300ms，可通过 AbortSignal 取消等待和请求。任务失败、不存在、缺少结果或超时均明确报告，不隐式重发写请求。

校准后探索、读取相遇时推进世界、探索面板三处共用这一规则。已完成但没有相遇是正常业务结果，不生成虚构同行者。校准已成功但后续探索失败时，提示明确保留“校准已保存”，避免误导用户。

本轮没有改变后端通信协议，仍为 HTTP 与轮询，不包含 SSE/WebSocket。取消前端请求不等于撤销服务端已执行的写入；超时后应刷新已有状态，而不是假定操作没有发生。

## 演示隔离

演示建号和校准集中至 `demo/`，仅显式独立演示模式使用。真实后端异常不会静默创建演示身份或编造相遇。保留原有独立演示模式检测和预设内容，不将其描述为真实双 Agent 生成。
